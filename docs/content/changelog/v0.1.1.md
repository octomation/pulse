# v0.1.1 — Always there.

pulse no longer needs a terminal tab. On macOS, Homebrew runs it as a background service: start it once, and the paper is at <http://pulse.localhost:17842/> every morning.

## A background service

```sh
brew services start octolab/tap/pulse
```

- The service runs as your user, without `sudo`, and starts again when you log in.
- `brew services restart octolab/tap/pulse` restarts it after an upgrade or after you change the config file; `brew services stop octolab/tap/pulse` ends it.
- What pulse says when it starts goes to `$(brew --prefix)/var/log/pulse.log`.
- `pulse` in a terminal works as before, for Linux, for an installation without Homebrew, or for another port. [Start it →](/trend-watch/#start-it)

## The GitHub token in the config file

A background service does not see the variables of your shell, so the reader can now take its GitHub token from `~/.config/pulse/config.toml`:

```toml
[github]
token = "github_pat_..."
```

- With a token the reader opens more than about 30 repositories an hour; a token without any permission is enough for public repositories.
- The token is kept as plain text: keep the file readable by you only. pulse sends it to `api.github.com` only and never prints it.
- `GITHUB_TOKEN` and `GH_TOKEN` still work for a pulse you run in a terminal, and come first. [The reader →](/trend-watch/#the-reader)

**Upgrade:** on macOS, run `brew update` followed by `brew upgrade --formula octolab/tap/pulse`, then `brew services start octolab/tap/pulse`; stop a `pulse` you run in a terminal first, since only one can listen on the port. With Go, run `go install go.octolab.org/toolset/pulse/cmd/...@v0.1.1`. For a manual installation, use a [v0.1.1 release archive](https://github.com/octomation/pulse/releases/tag/v0.1.1). Run `pulse version` and `pulsectl version` to check the installed version.
